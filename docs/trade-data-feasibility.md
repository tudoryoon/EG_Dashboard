# 수출입데이터 구축 검토

검토일: 2026-09-14. 이번 배포 범위는 상위 `수출입데이터` 탭과
`#/trade-data` 주소뿐이다. 수집기, 계산기, 기업 매핑, 정기 작업은 추가하지 않았다.

## 원문에서 확인한 내용

- [사용자 지정 글](https://m.blog.naver.com/jonber_man/224411168428)은 여러 나라의 수출입 통계를 기업 및 품목과 연결하고 실적 KPI와 비교하는 구조를 설명한다.
- 연결된 [CLS](https://m.blog.naver.com/jonber_man/224123130586), [LITE](https://m.blog.naver.com/jonber_man/224123131864), [CRDO](https://m.blog.naver.com/jonber_man/224123133827) 분석 글은 월간 합산 수출액 YoY, 3개월 누적 수출액 YoY, 단가 YoY를 제시한다.
- 읽을 수 있었던 본문에는 기업별 HS 코드, 국가별 포함 범위, 중복 제거 규칙, 가중치, 단가의 분모가 공개되어 있지 않았다. 이미지 내부의 세부 산식은 검증하지 못했다.
- 연결 서비스의 공개 페이지는 조사 환경에서 HTTP 403을 반환했다. 비공개 영역이나 내부 API는 조사하지 않았다.
- 실적 예측 정확도에 관한 주장은 독립 검증하지 않았다. 동일 수치 또는 예측 성능을 재현할 수 있다고 보장할 근거는 없다.

### 실제 원자료 읽기 검증

- [일본 e-Stat CSV](https://www.e-stat.go.jp/en/stat-search/file-download?fileKind=1&statInfId=000040494902): `Customs by Commodity by Country (Export Jan-Jul:Detailed)`, 품목 8525~8548, 2026년 7월 자료. 목록의 갱신일은 2026-08-28.
- 2026-09-14에 HTTP 200, `text/csv;charset=UTF-8`, 3,634,039바이트를 메모리에서 파싱했다. 대시보드 데이터 파일에는 저장하지 않았다.
- `Year`, `Custom`, `HS`, `Country`, `Unit2`, `Quantity2-Jan`~`Quantity2-Dec`, `Value-Jan`~`Value-Dec` 등 월별 열 확인. 위 두 HS 코드에 해당하는 행이 합계 117개 존재했다. 이는 국가/세관별 행 수이며 기업 수나 월 수가 아니다.
- 7월까지 제공된 파일에도 8~12월 열이 0으로 들어 있다. 수집기는 미발표 월을 수출 0으로 처리하면 안 된다. 최신 제공월까지만 채택해야 한다.
- 이 검증은 수집 가능성과 필드 구조 검증이다. 세관 코드의 정확한 범위, 금액 단위, 국가 합산, YoY 및 저자 수치와의 대조는 다음 구현 단계에서 별도 검증해야 한다.

## 독립 구현 가능한 계산

아래는 블로그의 비공개 산식을 복원한 것이 아니라, 공개 지표를 독립적으로 계산할 때 사용할 기본안이다.

- 월간 수출액: 사전에 확정한 국가/품목 시계열의 해당 월 금액 합계.
- 월간 YoY: `(이번 달 / 전년 동월 - 1) * 100`.
- 3개월 누적 YoY: `(최근 3개월 합계 / 전년 같은 3개월 합계 - 1) * 100`. 월별 YoY의 평균이 아님.
- 단위가치: 같은 품목 범위의 `금액 / 수량`. kg 자료라면 USD/kg로 표시하고 제품 개당 ASP라고 부르지 않음.
- 단가 YoY: 같은 분모 단위의 단위가치를 전년 동월과 비교. 0 또는 누락 분모는 결측 처리.

## 반드시 먼저 맞출 기준

1. 기업의 생산국, 제품, 수출 법인과 HS 코드의 연결 근거를 공시/IR로 기록한다. 국가/품목 통계를 기업의 실제 수출액으로 표시하지 않는다.
2. 서로 포함 관계인 HS 상위/하위 코드, 세계 합계와 국가별 합계를 동시에 더하지 않는다. 수출과 상대국 수입도 한 금액에 합산하지 않는다.
3. 통화, FOB/CIF, 개수/kg, HS 개정 및 회계분기를 맞춘다. 합산 대상에 누락 월이 있으면 완전한 합계처럼 표시하지 않는다.
4. 원자료의 기준월, 실제 공개일, 수집일, 개정 상태를 따로 저장한다. 실적 선행성 검증은 당시 이용 가능했던 데이터로만 수행한다.
5. 기업별 지표는 우선 대리지표로 취급한다. 24~36개월 자료로 기존 CANSLIM의 해당 사업 매출/성장률과 비교하되, 표본 외 검증 전에는 실적 예측 확률을 표시하지 않는다.

판정: 일본 Kioxia 사례는 저자가 밝힌 코드/세관 범위와 이를 제공하는 공식 CSV 경로를 찾았으므로 독립 수집의 출발점이 확보됐다. 태국 LITE는 세관 범위만 확인됐고 4개 코드 및 세관별 원자료 경로의 추가 검증이 필요하다.
월간 성장률, 3개월 누적 성장률, 단위가치와 그래프는 구현 가능하지만 기업별 수출액이나 블로그와 동일한 예측 결과로 표시할 근거는 없다. 다른 기업들의 매핑은 개별 검증 후 추가해야 한다.
